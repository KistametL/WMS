Nginx — Reverse Proxy

ทำไมต้องมี Nginx?

Nginx คือ "พนักงานต้อนรับ" ของ server รับ request ทุกอันเข้ามาที่ port 80 แล้วส่งต่อให้ service ที่ถูกต้อง ทำให้เปิดแค่ port เดียว จัดการ HTTPS ที่เดียว และป้องกัน service จริงไม่ให้เจอ internet โดยตรง

Browser → Nginx :80/:443 ├── / → Next.js :3000 ├── /api → Go Backend :8000 └── /pihole → Pi-hole :8080

docker-compose.yml

~/services/webserver/docker-compose.ymlYAML
services:
  nginx:
    image: nginx:alpine
    container_name: nginx
    restart: unless-stopped
    ports:
      - "80:80"          # port เดียวที่เปิดออก
    volumes:
      - ./conf.d:/etc/nginx/conf.d  # config files
      - ./html:/usr/share/nginx/html
    networks:
      - proxy            # network ร่วมกับ service อื่น

networks:
  proxy:
    name: proxy
    driver: bridge

conf.d/default.conf — Security Best Practices

~/services/webserver/conf.d/default.confNGINX
server {
    listen 80;
    server_name _;

    # ซ่อน version Nginx — hacker จะไม่รู้ว่าใช้ version อะไร
    server_tokens off;

    # บีบอัดไฟล์ก่อนส่ง browser ประหยัด bandwidth ~70%
    gzip on;
    gzip_types text/plain text/css application/json application/javascript;
    gzip_min_length 1000;

    # Security headers — ป้องกัน Clickjacking และ XSS
    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-XSS-Protection "1; mode=block";
    add_header X-Content-Type-Options "nosniff";

    location / {
        # ตัดการเชื่อมต่อถ้า backend ค้างเกิน 30 วินาที
        proxy_read_timeout 30s;
        proxy_connect_timeout 30s;

        # ต่อไปจะเปลี่ยนเป็น proxy_pass http://backend:8000
        return 200 'Nginx is running';
    }
}
ไม่ทำได้ไหม?

ได้ แต่ต้องเปิดหลาย port (3000, 8000, 8080...) ออก internet, HTTPS ซับซ้อนมาก, และ service แต่ละตัวเจอ attack โดยตรง

PostgreSQL + Redis

ทำไมต้อง 2 database?

PostgreSQL — ข้อมูลหลักทั้งหมด (users, orders, stock) รองรับ ACID transaction สำคัญมากสำหรับ WMS
Redis — เก็บ session, refresh token, cache — เร็วมากเพราะอยู่ใน memory

ทำไม PostgreSQL ไม่ใช่ MySQL

Featureความสำคัญกับ WMS
ACID Transactionหัก stock + สร้าง order ต้องเกิดพร้อมกัน ถ้า error ต้องย้อนกลับทั้งหมด
Row-level Lockingลูกค้า 2 คนซื้อพร้อมกัน — PostgreSQL ล็อก row ป้องกัน oversell
NUMERIC(15,2)ใช้แทน FLOAT สำหรับเงินเสมอ — FLOAT มี floating point error
JSONB supportเก็บ Shopee/Lazada raw data ที่ format ต่างกันได้ใน column เดียว

docker-compose.yml

~/services/database/docker-compose.ymlYAML
services:
  postgres:
    image: postgres:16-alpine
    container_name: postgres
    restart: unless-stopped
    environment:
      POSTGRES_USER: "${POSTGRES_USER}"     # อ่านจาก .env
      POSTGRES_PASSWORD: "${POSTGRES_PASSWORD}"
      POSTGRES_DB: "${POSTGRES_DB}"
    volumes:
      - ./data/postgres:/var/lib/postgresql/data
    ports:
      - "127.0.0.1:5432:5432"   # เข้าได้แค่จาก server เอง!
    networks:
      - proxy
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER}"]
      interval: 10s
      timeout: 5s
      retries: 5
    deploy:
      resources:
        limits:
          memory: 512m    # ป้องกัน RAM หมดทั้ง server
          cpus: '0.50'

  redis:
    image: redis:7-alpine
    container_name: redis
    restart: unless-stopped
    command: redis-server --requirepass "${REDIS_PASSWORD}"
    volumes:
      - ./data/redis:/data
    networks:
      - proxy
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "${REDIS_PASSWORD}", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5
    deploy:
      resources:
        limits:
          memory: 256m
          cpus: '0.25'
ทำไม 127.0.0.1 ไม่ใช่ 0.0.0.0?

0.0.0.0:5432 = ทุกคนใน network เข้า database ได้โดยตรง bot scan เจอและ brute force ได้ตลอด
127.0.0.1:5432 = เข้าได้แค่จาก server เอง ต้องผ่าน SSH tunnel เท่านั้น = Defense in Depth

Backup อัตโนมัติ

~/services/database/backup.shBASH
#!/bin/bash
set -e

source /home/kistamet/services/database/.env

BACKUP_DIR="/home/kistamet/backups/database"
DATE=$(date +%Y%m%d_%H%M%S)
FILE="$BACKUP_DIR/wms_db_$DATE.sql.gz"

docker compose -f /home/kistamet/services/database/docker-compose.yml \
  exec -T postgres pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" | gzip > "$FILE"

# เก็บแค่ 7 วันล่าสุด
find "$BACKUP_DIR" -name "*.sql.gz" -mtime +7 -delete

echo "Backup saved: $FILE"

Architecture Decisions

Modular Monolith — ไม่ใช่ Microservices

ทำไม?

Microservices ออกแบบมาสำหรับหลายทีมทำงานแยกกัน สำหรับ 2,000 orders/วัน monolith รับได้สบาย การทำ microservices ตั้งแต่แรกจะ slow down development 3-5x แต่แบ่ง module ชัดเจน สามารถ extract ออกเป็น service ทีหลังได้

Inventory Schema — หัวใจของ WMS

migrations/000003_create_inventory_schema.up.sqlSQL
CREATE TABLE inventory.stock_levels (
    sku_id        UUID    NOT NULL UNIQUE,
    qty_on_hand   INTEGER NOT NULL DEFAULT 0,
    qty_reserved  INTEGER NOT NULL DEFAULT 0,

    -- คำนวณอัตโนมัติ ไม่มีทางผิดพลาด
    qty_available INTEGER GENERATED ALWAYS AS
                  (qty_on_hand - qty_reserved) STORED,

    -- ป้องกันที่ database level ไม่ใช่แค่ application
    CONSTRAINT chk_no_negative    CHECK (qty_on_hand >= 0),
    CONSTRAINT chk_no_over_reserve CHECK (qty_reserved <= qty_on_hand)
);
ทำไม qty_available เป็น GENERATED COLUMN?

ถ้าคำนวณใน application code — ถ้ามีคนแก้ qty_on_hand โดยตรงใน database ค่าจะไม่ sync กัน GENERATED COLUMN คำนวณโดย PostgreSQL เสมอ ไม่มีทางผิด

Auth Schema — Security Design

migrations/000001_create_auth_schema.up.sqlSQL
-- UUID แทน SERIAL — ป้องกัน enumerate ID (ไม่มี /users/1, /users/2)
CREATE TABLE auth.users (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email         VARCHAR(255) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,  -- bcrypt hash เท่านั้น
    is_active     BOOLEAN NOT NULL DEFAULT TRUE,
    deleted_at    TIMESTAMPTZ,            -- soft delete ลบจริงไม่ได้
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- เก็บแค่ hash — ถ้า database หลุด token ใช้ไม่ได้
CREATE TABLE auth.refresh_tokens (
    token_hash VARCHAR(255) NOT NULL UNIQUE,
    expires_at TIMESTAMPTZ NOT NULL,
    revoked_at TIMESTAMPTZ              -- NULL = ยังใช้งานได้
);

-- บันทึกทุก action สำคัญ
CREATE TABLE auth.audit_logs (
    user_id     UUID,
    action      VARCHAR(100) NOT NULL,  -- "stock.adjust"
    entity_type VARCHAR(50),            -- "product"
    old_value   JSONB,
    new_value   JSONB,
    ip_address  INET,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

Go Backend — Auth Module

Flow การทำงาน

POST /api/v1/auth/login 1. Validate request (email format, password min 8) 2. GetUserByEmail → ไม่เจอ = ErrInvalidCredentials 3. bcrypt.CompareHashAndPassword → ผิด = ErrInvalidCredentials 4. GetUserRoles + GetUserPermissions 5. Generate JWT access token (24h, signed HS256) 6. Generate refresh token (random 32 bytes) 7. SHA256 hash refresh token → เก็บใน DB 8. Return tokens

sqlc — SQL → Go Code

internal/database/queries/auth.sqlSQL
-- name: GetUserByEmail :one
SELECT id, email, password_hash, first_name, last_name, is_active
FROM auth.users
WHERE email = $1 AND deleted_at IS NULL;

-- name: CreateRefreshToken :one
INSERT INTO auth.refresh_tokens (user_id, token_hash, expires_at)
VALUES ($1, $2, $3)
RETURNING id, user_id, expires_at, created_at;

Security — ทำไม hash refresh token

ถ้าเก็บ plain token ใน database

ถ้า database หลุด — แฮกเกอร์เห็น token ทั้งหมด สามารถ impersonate ทุก user ได้ทันที
ถ้าเก็บ SHA256 hash — token หลุดก็ใช้ไม่ได้ เพราะต้องมี plain token ถึงจะ hash ตรงได้

            cd ~/services/wms
            docker compose build --no-cache
            docker compose up -d
